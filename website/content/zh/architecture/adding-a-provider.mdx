`rship` 已内置 **10 个存储后端**，但整个工作区始终维持在 **7 个 crate**。新增存储后端无需新建 workspace crate——只需在 `rship-backends` 中添加一个按 feature 控制的模块，在 `rship` 里接入一次配置与工厂函数，再到 `rship-cli` 注册轻量 `ProviderAdapter` 即可。

## 每个后端必须遵守的核心不变量

1. **低内存（`<= 64 MiB` RSS）**：目录项通过有界 `mpsc::channel(256)`（`EntryStream`）流式产出；上传请求体直接流式发送，严禁把大文件整个读入内存；`open_read` 返回 `DataSource::RemoteRangeReadable`，以零内存占用支持云到云中继传输。
2. **崩溃可续传上传**：在 `Capabilities` 中声明精确分片参数（`UploadTopology::Sequential` 或 `ParallelParts`、`ChunkAlignment`、`single_shot_max_bytes`、`default_chunk_size`），并实现 `begin_upload`、`query_upload`、`upload_chunk`、`finish_upload`、`abort_upload` 与 `reconcile_operation`。
3. **复用公共基础设施**：
   - `rship_transport::HttpTransport`（H2/H1 双平面、`--proxy`、`--ca-cert`、停滞看门狗、CUBIC 限流器）
   - `rship_transport::oauth`（`PkceSession`、`OAuth2TokenManager`、`FileTokenStore`）
   - `rship_backends::common`（`rx_to_entry_stream`、`StrictBodyStream`、`ExactDownloadStream`、`common::http`、`common::crc`、`common::google_sa`、`common::xml`）
   - `rship_core::rclone_ini`（INI 解析与 AES-256-CTR 混淆密钥解密）

## 4 步接入后端 `foo`

### 第 1 步：新增模块 `crates/rship-backends/src/foo/`

```text
crates/rship-backends/
├── Cargo.toml                  # 新增 feature `foo = [...]`、可选依赖与 `[[test]]`
├── src/
│   ├── lib.rs                  # `#[cfg(feature = "foo")] pub mod foo;`
│   └── foo/
│       ├── mod.rs              # 重新导出 FooBackend、FooConfig、parse_rclone_foo_conf
│       ├── config.rs           # 强类型配置与分片对齐常量
│       ├── auth.rs             # 对 `rship_transport::oauth` 的薄封装（如使用 OAuth2）
│       ├── backend.rs          # `impl StorageBackend for FooBackend`
│       └── rclone_import.rs    # 可选的 `rclone.conf` 解析器
└── tests/
    └── foo_conformance.rs      # `required-features = ["foo"]`
```

### 第 2 步：实现 `StorageBackend` 并运行通用一致性套件

实现必需的标识与命名空间方法（`stat`、`list_stream`、`mkdir`、`delete`、`compute_hash`、`open_read`）及断点续传上传方法，并按需覆写高收益可选方法（`delete_batch`、`can_server_side_copy_from` / `server_side_copy`、`about`、`rename`）。

随后在 `foo_conformance.rs` 中一行调用即可校验全部 9 项通用不变量：

```rust
rship_core::conformance::run_backend_conformance(Arc::new(backend), clock).await;
```

```bash
# 开发期间的快速隔离测试循环
cargo test -p rship-backends --no-default-features --features foo
```

### 第 3 步：在 `rship-core` 与 `crates/rship` 一次性接入类型、配置与工厂

由于 `rship-cli` 的 `CliRuntime` 直接复用 `RshipClient`，在 `rship-core` 与 `crates/rship` 完成接入后，Rust SDK（`RshipClient`）与 `rship-cli` 会同步生效：

1. **`crates/rship-core/src/types.rs`**：新增 `BackendKind::Foo` 及其 `as_str()` / `parse()` 分支。
2. **`crates/rship/Cargo.toml`**：新增特性 `foo = ["rship-backends/foo", "http"]`（非 HTTP 后端省去 `"http"`），并将 `"foo"` 加入 `all-backends`。
3. **`crates/rship/src/config.rs`**：新增 `#[must_use] #[non_exhaustive] pub struct FooRemoteConfig`（配齐 `::new(...)` 与链式 `with_*` 构造器及脱敏 `Debug`）、`RemoteConfig::Foo(Box<FooRemoteConfig>)`、`From<FooRemoteConfig> for RemoteConfig`，并接入 `kind()` 与 `visit_secrets` / `visit_secrets_mut`（脱敏、内联密钥统计与系统密钥环迁移/清理的唯一事实来源）。
4. **`crates/rship/src/lib.rs` 与 `prelude.rs`**：重新导出 `FooRemoteConfig`。
5. **`crates/rship/src/factory.rs`**：在 `build_remote_backend`、`target_needs_transport`（如非 HTTP 协议）中处理 `RemoteConfig::Foo`（若支持导入 `rclone.conf`，同步接入 `import_rclone_conf*`）。

### 第 4 步：在 `rship-cli` 注册认证与生命周期适配

1. **`crates/rship-cli/Cargo.toml`**：在 features 与 `all-backends` 中添加 `backend-foo = ["rship/foo", "rship-backends/foo"]`。
2. **`crates/rship-cli/src/cli.rs`**：新增 `FooAuthArgs` 与 `AuthAction::Foo(FooAuthArgs)`。
3. **`crates/rship-cli/src/ops/config_ops.rs`**：补齐 `RemoteConfig::Foo` 的摘要展示、描述、排序与别名。
4. **`crates/rship-cli/src/providers/foo.rs` + `providers/mod.rs`**：实现 `ProviderAdapter`（`kind`、`rclone_type`、可选侧车令牌清理 `cleanup_secrets`、复用 `abort_gc_for_remotes` 的 `abort_gc_operation`、`export_bundle`、`import_bundle`）与 `handle_auth`，在 `registered_providers()` 中注册 `&foo::FooAdapter`，并在 `dispatch_provider_auth` 中分发 `AuthAction::Foo`。敏感信息脱敏与系统密钥环迁移会经由 `RemoteConfig::visit_secrets*` 自动生效。

注册完成后，所有命令（`copy`、`sync`、`move`、`bisync`、`check`、`hashsum`、`cat`、`rcat`、`about`、`tree`、`gc`、`config`、`auth export|import|keyring-migrate` 以及 `crypt` 加密覆盖远端）都会自动支持该后端。
