# Changelog

All notable changes to `rship` are documented in this file.

## [0.1.0] - 2026-11-27

> This 0.1.0 build supersedes the artifacts first published under the `v0.1.0` tag on 2026-11-26, which were built from a commit that had not passed CI. Persisted state from that build (`journal.db`, baselines) is upgraded automatically.

### Added
- **Ergonomic Rust SDK Facade (`rship`) & Hardened Public API Contracts**:
  - Top-level `rship` SDK crate (`#![warn(missing_docs)]`, lean `default = ["local"]` feature graph, zero `anyhow` in library API) providing `RshipClient`, `ClientBuilder`, `TransferBuilder`, `BisyncBuilder`, `TransferTarget` (strings, `Path`, `TargetPath`, or pre-resolved `FailoverPool` backends), cached remote backend reuse, pure in-memory ephemeral `rclone.conf` loading (zero disk writes), active-job-tracked graceful `shutdown()`, and shared `config`/`secrets`/`factory` layers consumed directly by `rship-cli`.
  - SemVer-hardened `#[non_exhaustive]` contracts, standard trait impls (`FromStr`, `TryFrom`, `AsRef`, `Display`, `Serialize`/`Deserialize`), semantic `Error` predicates, typed `FileTransferResult.error_kind` & `RunReport.error_details`, panic-isolated sequenced push `TransferEvent`/`EventSink` + bounded `ChannelEventSink` across transfers and `bisync`, SQLite-free `MemoryJournalStore` & `MemorySyncIndex` with source/destination case-insensitive collision detection, and instant cancellation during retry backoff.
- **Low-Memory Streaming Core Engine (`rship-core`, `rship-state`)**:

### Defaults & API Contracts
- **`StorageBackend` trait expansion (`rship-core`)**: Added default methods `prepare_operation_id`, `flush_durable_writes`, and `sync_durable_file` to support pre-generated remote operation IDs and batch/per-file durability hooks.
- **Local durability mode (`FsyncMode` & `--fsync`)**: Added `FsyncMode::{Always, Batch, Never}` (default: `Batch`) across `rship-core`, `rship` (`resolve_with_fsync` / `resolve_file_with_fsync`), `LocalBackend`, and CLI transfer/bisync commands (`--fsync=always|batch|never`). Normal local writes now batch-flush before baseline/job commits and deletion passes, while source deletions in `move` and `bisync` unconditionally flush the destination file and parent directory first.
- **`bisync` default delete safety cap**: `BisyncConfig::max_delete_percent` now defaults to `Some(50.0)` (`--max-delete 50%`). Explicit `max_delete` takes precedence when set; pass `None` to disable percentage gating.
- **S3 upload checksum default**: `S3Config::send_upload_checksum` now defaults to `true`, sending provider-supported `CRC64NVME` / `CRC32C` upload checksums and verifying streaming upload/download checksums without disk spooling.
- **S3 single-request `CopyObject` cutoff**: Lowered `DEFAULT_MAX_SINGLE_COPY_BYTES` to `512 MiB` (larger server-side copies automatically switch to multipart `UploadPartCopy`).
- **Missing local root error**: `LocalBackend::list_with_options` (and `list_stream`) now returns `ErrorKind::NotFound` when the local root directory does not exist instead of yielding an empty listing, preventing unmounted disks from triggering mass sync/bisync deletions.
- **Single retry layer contract**: Added `Error::retries_exhausted: bool` (plus `retries_exhausted()` / `with_retries_exhausted()`) on `rship_core::Error` so exhausted lower-layer backend retries are not retried again by outer engine loops.
- **Transport timeout & limiter isolation types (`rship-transport`)**: Added `LimiterPlane::{Control, Data}` on `LimiterScope` and extended `TransportConfig` with `long_control_timeout` (`300 s` default) and `data_finalize_timeout` (`300 s` default).

### Durability & Data-Loss Fixes
- **Stale reconciliation version check (D1)**: Verify `existing.src_version == current_src_ver` before accepting a stale `Completing` / `NeedsReconciliation` journal entry as completing the current transfer, ensuring post-crash source edits upload the new version instead of skipping or deleting the modified source in `move`.
- **Configurable local durability & mandatory move sync (D2)**: Implement `--fsync=always|batch|never` (`batch` default) with OS-specific batch flushing (`syncfs(2)` on Linux with per-file/dir fallback, `FlushFileBuffers` on Windows, per-file/dir `fsync` on macOS/other Unix) before baseline/job commits and deletions, plus unconditional `sync_durable_file` (`sync_all` + POSIX parent-dir fsync) before any source deletion in `move` or `bisync`.
- **Bisync empty-side & mass-delete protection (D3)**: Persist `bisync_state` early (right after Phase 1 observation / before Phase 2 transfers) and check existing pair baselines so interrupted first runs arm the empty-side guard; enforce default `--max-delete 50%` on `bisync` while emitting `RunReport::high_delete_warning` above 50% on `sync` without aborting; reject missing local roots with `ErrorKind::NotFound`.
- **Precondition & live-version verification (D4)**: Enforce `DstPrecondition` (`Absent` / `Existing { size, mtime_ns }`) immediately before atomic rename in `LocalBackend::{put_single_shot, server_side_copy, finish_upload}`; re-stat and verify observed `SourceVersion` before `bisync` Phase-3 deletes and Phase-2 overwrites on backends lacking native conditional writes.
- **Google Drive pre-generated IDs (D5)**: Pre-generate globally unique file/folder IDs via `files.generateIds` and persist `remote_op_id` via `prepare_operation_id` before single-shot uploads, `files.copy`, and folder creation (`mkdir`) so crash recovery reconciles deterministically without duplicates (mock-verified).
- **Atomic SQLite group-commit rollback (D6)**: Roll back the entire `journal.db` group-commit transaction and propagate the error to every touched batch write if `UPDATE jobs` counter preparation/execution or `COMMIT` fails.
- **Full journal durability & WAL truncation (D7)**: Switch `journal.db` to `PRAGMA synchronous = FULL` and run `PRAGMA wal_checkpoint(PASSIVE)` + `PRAGMA wal_checkpoint(TRUNCATE)` on both `Flush` and `Shutdown` (keeping ephemeral spilled `SqliteSyncIndex` at `synchronous = OFF`).
- **Cross-platform racily-clean guard (D8)**: Raise `LocalBackend::capabilities().mtime_granularity` to `10 ms` across platforms to guard against coarse kernel timestamp ticks.
- **Race-free `ProcessLock` sweeping & scope docs (D9, D10)**: Unlink stale `.lock` files only while holding the exclusive lock in `sweep_stale_locks`, verify live file identity (`dev`/`ino` on Unix; `creation_time` + probe-lock contention on Windows) in `ProcessLock::try_acquire_file`, and explicitly document overlapping-prefix lock scopes (e.g. `a` vs. `a/b`) as unsupported.
- **SQLite schema versioning & ordered migrations (D11)**: Track `PRAGMA user_version` across `journal.db`, baseline shards, and inventory shards with ordered `BEGIN IMMEDIATE` migrations, unversioned pre-release DBs treated as version 1, and explicit refusal to open newer schema versions.
- **Clean job finalization on early errors (D12)**: Mark jobs `Failed` and cleanly drain/join aborted workers when early producer, observation, or bisync errors occur instead of leaving stale `Running` records.
- **Safe SQLite shard deletion ordering (D13)**: Remove companion `-wal` and `-shm` files before the main `.db` file so orphaned WALs can never replay onto recreated shards.
- **Tight `BufferPool` crypto slab release (C2)**: Reset drained `Bytes` slices to `Bytes::new()` before awaiting or polling the next upstream chunk in `rship-crypto` (`CryptoRangeReader`, `open_full_decrypt_stream`, `StreamEncryptor`), preventing deadlocks under 1-slab and 2-slab `BufferPool` caps.

### Verification-Pass Hardening
- **Integrity errors are never reconciled into success**: new `ErrorKind::Integrity` / `RetryClass::Integrity` for every checksum mismatch. Mismatches are never retried in place, never count as throttle signals, and never pass through reconcile; the transfer is retried from scratch (at most twice), a corrupt object we created is deleted, and one that cannot be removed gets a persisted `integrity_failed` journal marker that forces re-transfer and blocks skips, baselines, bisync convergence, and `move` source deletes until a verified transfer clears it (`rship jobs cleanup` never removes markers).
- **Chunked and ranged reads verified end to end**: sequential sessions keep a running SHA-256/CRC-32C and hold back the final bytes until it matches the source's full-object checksum; parallel multipart combines per-part CRC-32C (new public `rship_core::crc32c` with `crc32c_combine`). GCS resumable uploads stream CRC32C and send `x-goog-hash` on the final request; OneDrive verifies with streaming QuickXorHash; Nextcloud/ownCloud WebDAV use `X-Hash` / `OC-Checksum`. See the per-provider matrix in `ARCHITECTURE.md`; SFTP and generic WebDAV remain length-checked only.
- **`--fsync=batch` durability fence**: baseline rows, operation retirements, and terminal job states are committed only after a destination flush that covers their data (`DurabilityFence`, `StorageBackend::defers_durable_writes`), draining every 1,024 records or 2 s and on cancel/error paths. A failed flush fails the job and drops that batch's records. `move` now fsyncs the destination, commits the record durably (`JournalStore::commit_verified_transfer_durable`), then verifies and deletes the source. After a crash, leftover files are hash-verified or re-copied before they are trusted.
- **Local durability**: directory fsync errors and `syncfs` `EIO` propagate (only filesystems that cannot fsync directories are tolerated); failed batches keep their pending paths; newly created intermediate directories are fsynced on durable commits; Windows racily-clean window is `20 ms`; writes over NFD-named destinations reuse the on-disk spelling.
- **`crypt:` forwards every backend hook** (`sync_durable_file`, `flush_durable_writes`, `defers_durable_writes`, `prepare_operation_id`, `retry_quota`) so `move` to crypt-over-local is durable and GDrive pre-generated IDs work under crypt; crypt single-shot overwrites on local and reconcile of single-shot crypt ops are fixed.
- **Delete safety**: a panicking or dead transfer worker now fails the run and marks source observation incomplete on the indexed, pipelined, and streaming-merge paths, so `--delete-after` never deletes files the listing had not reached. `--files-from` with a missing source root is an error.
- **Non-idempotent provider commits reconciled, not blindly retried**: Azure `PutBlockList`/`CopyBlob` and GCS `rewriteTo` (op-id metadata + size), Dropbox `copy_v2`/`move_v2`/`upload_session/finish`, OneDrive `items.copy`/`createFolder`. WebDAV `COPY` reconcile now requires the destination to change from a pre-COPY snapshot. A `429` is resent without reconciling. Azure block-list uploads report the real whole-blob MD5 (previously the MD5 of the request XML).
- **Reconcile requires proof, never size alone**: OneDrive, Dropbox, WebDAV, SFTP, and local upload reconcile accept an object only when its size, the mtime we set, and a changed version identity (eTag, `rev`, ETag, `dev`+`ino`) prove it is the operation's result; otherwise the file is transferred again. A same-size older file left at the destination can no longer be accepted after an expired session or crash, which could have let `move` delete the only good source. GCS `308` responses without `Range` and OneDrive `202` responses without `nextExpectedRanges` now mean "nothing persisted" / "re-query", not "chunk stored".
- **S3 multipart checksum contract**: sessions record their part checksum algorithm; `finish_upload` fills missing COMPOSITE part checksums from `ListParts`; the S3 mock enforces AWS's Create/UploadPart/Complete checksum rules.
- **One retry budget**: engine and backend retries share one bucket per destination `(remote, principal)` (`StorageBackend::retry_quota()`), shared across whole `sync`/`bisync` runs, with a single `30 s` backoff and `Retry-After` cap (`DEFAULT_MAX_RETRY_DELAY`). `ReconcileAction::Retry` carries the original error so source chains survive.
- **Bounded response bodies**: data-plane response bodies are read with idle and total deadlines (`HttpTransport::read_data_body`), so a server that sends headers and then stalls can no longer hang a transfer.
- **OAuth**: a refreshed token is kept in memory even if persisting it fails, so rotated refresh tokens are not lost.
- **Memory**: pipelined listings bound non-ASCII/NFD names through the spilling sync index; planned `move` skips run on a bounded background executor instead of stalling listing.
- **Reproducible simulation**: seedable retry jitter (`EngineConfig::with_retry_jitter_seed`), retry and limiter sleeps routed through the injected clock, DST and the crash-at-every-step sweep extended to `move`, `sync` with baselines and deletes, multi-file runs, the pipelined and streaming-merge paths, and the SQLite `StateActor` journal. nextest no longer retries DST/chaos/crash-sweep tests.
- **Dependencies & CI**: replaced the unmaintained `chrono` with `jiff` (RUSTSEC-2026-0543) behind a golden-tested `rship_core::time` module (`AzureAuth::sign_headers` now takes `jiff::Timestamp`); CI and release build on stable while the MSRV job pins `1.100.0`; nightly fuzz smoke for all 5 fuzz targets; the first `--json-progress` tick is delayed one interval so it cannot race a fatal error.
- **API cleanups**: removed the inert `EngineConfig`/`BisyncConfig` `fsync_mode` (set `FsyncMode` on the local backend); `RunScratchDir::ensure_subdir` is async; new `DstPrecondition::may_exist`.
